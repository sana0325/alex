# Мульти-ринок ШІ Скальп-бот (BingX)

Мобільний застосунок (React + Capacitor) для автоматичної скальп-торгівлі
золотом, криптою та іншими парами через **BingX** (USDT-M Perpetual Swap
API) з плечем 20x. Рішення про вхід приймає ШІ **DeepSeek** за стратегією
Smart Money Concepts, розмір ставки росте драбиною разом із балансом
рахунку, а кожна угода лягає в журнал — раз на два дні бот сам аналізує,
що спрацювало, а що ні, і робить висновки на майбутнє.

⚠️ **Це реальна торгівля реальними коштами.** Замовлення відправляються на
біржу одразу після сигналу ШІ (перемикач "LIVE" у налаштуваннях можна
вимкнути, щоб бот тільки рахував сигнали без відправки ордерів).

## Можливості

- **Два екрани**: "Торгівля" (графік, живі позиції, статус ШІ) і "Журнал"
  (історія угод, вінрейт, ШІ-розбір раз на 2 дні).
- **22 пари**: BTC, ETH, SOL, BNB, XRP, DOGE, ADA, LINK, AVAX, LTC, GRAM, DOT,
  MATIC, SHIB, PEPE, NEAR, APT, ARB, OP, SUI, ATOM і золото (через PAXG-USDT —
  токенізоване золото; BingX не надає скриптований класичний XAUUSD на цьому
  API). Бот ротаційно сканує всі пари одразу, а не сидить на одній — але
  **чекає, поки поточна угода повністю не відпрацює (TP/SL чи ручне
  закриття), перш ніж відкрити наступну** (`MAX_OPEN_POSITIONS = 1` у
  `constants.ts`).
- **Лімітні ордери-мейкери**: вхід виставляється лімітним ордером (PostOnly)
  рівно по ціні сигналу ШІ, а не ринковим — менше спреду й комісії. Якщо
  ордер не виконався за 3 хвилини або ціна пішла вбік, бот сам скасовує його
  й шукає далі.
- **Драбина ставок**: маржа на угоду зростає разом із балансом рахунку
  (`constants.ts` → `STAKE_LADDER`, стартує з $2).
- **Плече 20x** за замовчуванням (`Налаштування → Плече`).
- **Завжди навчається, навіть без підключення до біржі**: якщо BingX не
  підключений або вимкнено LIVE, бот все одно тягне реальні ринкові дані,
  сам "торгує на демо" (віртуальний баланс, стартує з $200) — заходить і
  виходить по своїх же сигналах, пише в той самий журнал і так само вчиться.
- **Журнал угод**: кожна закрита угода (реальна чи демо) записується з
  причиною входу від ШІ, сетапом, результатом.
- **Самонавчання**: у кожен запит до ШІ на новий сигнал підмішується
  статистика журналу (вінрейт, розбивка по сетапах) і висновки з останнього
  ретроспективного розбору — бот щодня "бачить" свою історію.
- **Розбір раз на 2 дні**: окремий виклик ШІ аналізує всі угоди за період і
  формулює конкретні правила на майбутнє; можна запустити вручну кнопкою
  "Аналізувати зараз" у Журналі.
- **Push-сповіщення**: однаково і на демо, і в LIVE-режимі —
  - при вході: "📡 Сигнал LONG: BTC-USDT — Угода відкрита (демо)" /
    "...(LIVE режим)";
  - при виході: "Угода в плюсі: BTC-USDT +4.00$ (+2.1%) · Баланс: $24.00".

### Про фонову роботу

Android призупиняє JS-таймери WebView-застосунків одразу, як тільки екран
згортається — тому раніше бот "засинав" у фоні. Тепер **весь торговий
"мозок" — сканування пар, запит до DeepSeek, перевірка сетапу, вхід в
угоду, нагляд до закриття — працює й нативно** (`TradingWatchService.java`,
foreground-сервіс з постійною іконкою в шторці сповіщень), повністю
незалежно від WebView. Коли застосунок згортається, він передає сервісу
знімок налаштувань (ключі, плече, LIVE/демо, список пар, драбина ставок,
поточний баланс, висновки з останнього розбору журналу) і — якщо вже щось
відкрито — саму угоду чи лімітний ордер. Сервіс продовжує повний цикл сам:
шукає сетап → відкриває (лімітний ордер на біржі чи демо-угоду) → доглядає
до закриття → шукає далі — доки застосунок згорнутий. Коли застосунок
відкривається знову, він забирає керування назад і дописує в журнал усе,
що сервіс встиг зробити, поки був у фоні (можливо, кілька угод підряд).

Чесно про межі цього рішення:
- **OEM-оболонки з агресивним керуванням батареєю** (MIUI/Xiaomi, EMUI/Huawei,
  ColorOS/Oppo тощо) можуть все одно вбити фоновий сервіс, якщо застосунок не
  додано вручну у виключення батареї / автозапуск. Це поширена проблема саме
  на пристроях, популярних в Україні — після встановлення варто зайти в
  налаштування батареї телефону і дозволити застосунку працювати без обмежень.
- Android накладає м'яке обмеження ~6 годин на foreground-сервіси типу
  `dataSync` на добу — якщо сесія у фоні триває довше, система теоретично
  може зупинити сервіс раніше часу.
- Промпт для ШІ й математика входу/виходу продубльовані в Java (щоб не
  залежати від WebView) — логічно ідентичні `services/aiTrader.ts` і
  `services/bingx.ts`, але це два джерела істини, які треба міняти
  синхронно при майбутніх правках стратегії.
- Для абсолютної 24/7-гарантії (як з ботами на сервері) найнадійніший варіант
  — окремий завжди увімкнений процес (сервер/VPS), а не телефон; це можна
  зробити пізніше на базі того самого `services/bingx.ts`.

## Запуск локально

**Залежності:** Node.js

1. `npm install`
2. Запустити: `npm run dev`
3. У застосунку відкрити ⚙ Налаштування і вказати:
   - **BingX API Key / Secret** — створіть на bingx.com з правом торгівлі
     на Perpetual Futures (без права виводу коштів).
   - **DeepSeek API ключ** — для аналізу сигналів і журналу.
   - **Плече** (за замовчуванням 20).
   - Перемикач **LIVE** — вимкніть, якщо хочете спершу просто подивитись,
     які сигнали видає ШІ, без реальних ордерів.

## Збірка під Android

```
npm run cap:add:android   # один раз
npm run cap:build         # build + cap sync
npm run cap:open          # відкрити в Android Studio
```

## Архітектура

- `services/bingx.ts` — підписаний HMAC-SHA256 клієнт до BingX Swap API
  (баланс, контракти, свічки, позиції, плече, ордери). Підпис рахується на
  пристрої (Web Crypto), секретний ключ нікуди не надсилається, крім самої
  біржі.
- `services/aiTrader.ts` — промпти й виклики DeepSeek: живий скальп-сигнал
  та ретроспективний розбір журналу.
- `services/journal.ts` — журнал угод, статистика, розклад розбору раз на
  2 дні, локальний трекінг відкритих угод (localStorage).
- `App.tsx` — опитує BingX (баланс/позиції/свічки), ротаційно сканує пари
  через ШІ, виконує вхід/вихід і веде журнал.

**Свічки — тільки з BingX.** Джерело даних для аналізу — виключно офіційний
`GET /openApi/swap/v3/quote/klines` самої біржі (`bingx.getKlines`,
однаково і в `App.tsx`, і в нативному `TradingWatchService.java`), без
жодних сторонніх/публічних агрегаторів — це і швидше (одна ланка замість
проксі через чужий сервіс), і менша затримка між свічкою на біржі й тим, що
бачить ШІ. Це так само і на демо, і на реальному рахунку — обидва режими
торгують по одних і тих самих цінах з BingX, різниться лише виконання
ордера (реальний ордер на біржі проти віртуального балансу).

`bridge/` — застарілий MT5-міст (Python) з попередньої ітерації проєкту
(робота через MetaTrader5 для форекс/золота); поточна версія бота працює
напряму через BingX API і цей міст більше не задіяний.
